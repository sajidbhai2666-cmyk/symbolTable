EXECUTIVE RELEASE STATUS
The Symbol Table Generator and Compiler Scope/Memory Analyzer is a production-grade full-stack developer tool designed for compiler engineers, systems developers, and students. The application operates with a zero-database footprint, executing high-speed lexical, scoping, semantic, memory sizing, and hash table simulations entirely in-memory and client-side within the browser.

1. Executive Summary & Core Value Proposition

In modern compiler construction, the Symbol Table is the central nerve center responsible for storing identifiers, resolving variable bindings, tracking static lexical scoping, evaluating storage classes, computing hardware memory offsets, and validating semantic correctness.

The Symbol Table Generator & Compiler Analyzer integrates the industrial-grade Monaco Editor (the core engine of Microsoft VS Code) with an isomorphic multi-language compilation engine. The software analyzes source code written in C, C++, Java, JavaScript, and Python, immediately projecting the compiler's internal representations across four interactive visual views:

  • Tabular Symbol Table: Searchable, filterable symbol inventory displaying kind badges, qualified data types, lexical scope nesting levels, exact definition positions, and memory offsets.
  • Hierarchical Scope Tree: An interactive visual representation of nested lexical environments (Global Scope, Functions, Blocks, Loops, Structs/Classes).
  • 16-Bucket Hash Table Simulator: Visualizes compiler symbol table indexing using polynomial rolling hashing and separate chaining collision resolution with load factor metrics.
  • Memory Layout & Activation Record: Simulates System V AMD64 ABI memory alignment, global data segment offsets (.data/.bss), stack frame base pointer offsets ([rbp - n]), and register allocation for function parameters (%rdi–%r9).

3. Functional Requirements Specification

The functional requirements define all behavioral capabilities, input parameters, transformations, and outputs of the compiler analysis system.

ID Requirement Name Functional Description & Input / Output Priority Module
FR-01 Multi-Language Lexical Tokenization The system must tokenize source code into typed tokens (KEYWORD, TYPE, STORAGE, IDENTIFIER, NUMBER, STRING, COMMENT, OPERATOR, DELIMITER, PREPROCESSOR) for C, C++, Java, JavaScript, and Python. Handles multi-character operators (e.g. >>=, ->, ::) and escaped literals without truncation. P1 - High tokenizer.js
FR-02 Hierarchical Lexical Scope Tree Constructs an n-ary tree of lexical environments starting from Global Scope (Level 0) down through nested functions, blocks, loops, and composite types. Every scope must track its unique identifier, enclosing parent ID, nesting level, and line range (startLine to endLine). P1 - High symbolTable.js
FR-03 Symbol Record Extraction & Attributes For every declared identifier, extracts: Name, Kind (variable, function, parameter, constant, struct, class, typedef), Qualified Data Type, Scope ID & Name, Line, Column, Size in bytes, Memory Offset, Storage Class, and array dimensions. P1 - High symbolTable.js
FR-04 Duplicate Redeclaration Detection The semantic engine must evaluate whether an identifier has already been declared within the exact same scope via scope.hasLocal(name). If duplicate, flags symbol as isRedeclaration = true and emits an Error severity diagnostic with previous definition coordinates. P1 - High symbolTable.js
FR-05 Variable Shadowing Detection When an identifier is declared in a child scope, the engine traverses parent scopes via scope.parent.lookup(name). If an outer symbol with the same name exists, flags isShadowed = true and emits a Warning specifying the shadowed scope and line. P1 - High symbolTable.js
FR-06 Undeclared Identifier Resolution Validates every variable reference against the lexical scope chain. Emits an Error diagnostic if no matching declaration exists. Standard library identifiers (printf, malloc, cout, cin, Math, console, etc.) are whitelisted. P1 - High symbolTable.js
FR-07 Unused Identifier Analysis Evaluates reference occurrence counts after parsing. Flags identifiers with zero references as Notice/Warning. Struct/class member variables, composite type definitions, and main() are exempted. P2 - Med symbolTable.js
FR-08 AMD64 Memory Offset Calculation Computes byte sizing with 64-bit alignment:
  • Global variables: Positive data segment offsets (+0x0000, +0x0004).
  • Local variables: Negative stack pointer displacements ([rbp - 4], [rbp - 8]).
  • First 6 parameters: AMD64 registers (%rdi, %rsi, %rdx, %rcx, %r8, %r9).
  • Struct members: Zero-indexed cumulative member offsets (Member: +0x0000).
 P1 - High memoryLayout.js
FR-09 16-Bucket Hash Table Simulation Simulates closed-addressing hash table lookup using polynomial rolling hash H(k) = (∑ c_i * 31) % 16. Displays bucket chains, collision counts, and load factor (α). P2 - Med memoryLayout.js
FR-10 Monaco Editor Diagnostics & Markers Transforms compiler diagnostics directly into native Monaco squiggles (monaco.editor.setModelMarkers). Errors render with red squiggles; warnings render with yellow squiggles. P1 - High editor.js
FR-11 Bidirectional Cursor Navigation Clicking any symbol row in the Symbol Table, Scope Tree chip, or Hash Bucket entry jumps Monaco cursor to definition coordinates and animates a pulse highlight. Clicking a scope highlights its line span. P2 - Med editor.js / app.js
FR-12 Interactive Search & Filter Controls Users can filter the Symbol Table via a live keyword search box, kind filter chips (All, Variables, Functions, Params, Constants, Structs), and scope level dropdown. P2 - Med visualizer.js
FR-13 Multi-Format Data Exporter Exports complete symbol table snapshots to structured JSON, spreadsheet CSV, GitHub Flavored Markdown, and academic booktabs LaTeX (.tex). P2 - Med export.js
FR-14 Dual Client/Server Architecture The compiler runs directly in-browser for static servers (VS Code Live Server, GitHub Pages, file:///) with zero setup, while also exposing a REST endpoint (POST /api/analyze) for Node.js workflows. P1 - High app.js / api.js

5. Use Case Specifications

The following detailed use cases articulate primary end-user interaction workflows, system state transitions, preconditions, and postconditions.

UC-01: Real-Time Symbol Table Generation & Scope Analysis

Use Case ID & NameUC-01: Real-Time Symbol Table Generation
Primary ActorCompiler Student / Systems Developer
PreconditionsWeb application is loaded in a modern web browser. Monaco editor is initialized.
TriggerActor types code into Monaco Editor or selects a pre-configured sample preset from the dropdown.
Main Scenario
  1. Actor types or pastes multi-scope C code into the editor.
  2. Editor triggers debounced change event (600ms idle threshold) or actor presses Ctrl+Enter.
  3. app.js invokes Compiler.analyzeSourceCode(code, language).
  4. Lexer scans characters into tokens; Scope builder constructs tree of lexical environments.
  5. Semantic verifier evaluates redeclarations, shadowing, references, and unused variables.
  6. Memory analyzer assigns AMD64 data offsets, stack displacements, and hash buckets.
  7. Visualizer renders populated Symbol Table, updates scope tree hierarchy, and refreshes counters.
  8. Monaco updates inline squiggles matching compiler diagnostics.
PostconditionsSymbol table table displays all identifiers; Monaco displays diagnostic squiggles.

UC-02: Identifying & Resolving Semantic Compiler Errors

Use Case ID & NameUC-02: Semantic Error Detection & Visual Squiggles
Primary ActorSoftware Developer / QA Engineer
PreconditionsSource code contains semantic anomalies (e.g. duplicate declaration or undeclared variable).
TriggerActor selects "Semantic Errors Showcase" sample preset.
Main Scenario
  1. Actor loads code containing duplicate global int totalCount = 10; int totalCount = 20;.
  2. Compiler detects scope.hasLocal("totalCount") is true for the second declaration.
  3. Redeclaration error is flagged: cites previous declaration at Line 1, Col 5.
  4. Monaco highlights the offending line with red compiler squiggles.
  5. The bottom Diagnostics drawer expands, listing the exact error message and clickable position badge.
  6. Actor clicks the diagnostic row in the drawer: cursor jumps directly to the conflicting declaration.
PostconditionsActor immediately locates and resolves compiler errors before code generation.

UC-03: Inspecting Variable Shadowing Across Lexical Environments

Use Case ID & NameUC-03: Variable Shadowing Inspection
Primary ActorComputer Science Student
PreconditionsCode contains nested block scopes declaring identical identifier names.
TriggerActor selects "Lexical Scoping & Shadowing" preset.
Main Scenario
  1. Actor observes int x = 1000; at Level 0, int x = 100; in function, and int x = 10; in block.
  2. Compiler marks inner x instances with isShadowed = true and tags the parent target.
  3. Symbol Table displays a yellow "Shadowed" status badge next to inner identifiers.
  4. Actor switches to Scope Tree tab: views parent-child nesting with local variable chips.
PostconditionsActor gains visual clarity on variable lifetime and scoping rules.

UC-04: Analyzing AMD64 Memory Layout & Stack Frame Allocations

Use Case ID & NameUC-04: Memory & Stack Frame Visualization
Primary ActorSystems Programmer / Assembly Enthusiast
PreconditionsCode defines global variables, functions with parameters, and local variables.
TriggerActor clicks the "Memory & Stack" navigation tab.
Main Scenario
  1. Visualizer partitions symbols into Global Data Segment and Activation Record (Stack Frame).
  2. Global variables show cumulative positive hex offsets (+0x0000, +0x0004).
  3. First 6 parameters display hardware AMD64 calling convention registers (%rdi, %rsi, etc.).
  4. Local variables display stack displacements relative to base pointer ([rbp - 4], [rbp - 8]).
  5. Memory block diagram illustrates caller saved frame (RIP + saved RBP) down to current stack pointer (RSP).
PostconditionsActor verifies memory sizing and alignment before low-level code compilation.

UC-05: Simulating Compiler Internal Hash Table Collisions

Use Case ID & NameUC-05: Hash Table Collision Simulation
Primary ActorData Structures & Compiler Student
PreconditionsSymbol table contains multiple identifiers.
TriggerActor clicks the "Hash Buckets" navigation tab.
Main Scenario
  1. System passes symbols through polynomial rolling hash algorithm across 16 buckets.
  2. Grid displays all 16 buckets with entry counts, load factor (α), and separate chaining links.
  3. Buckets with collisions highlight chain nodes with downward traversal pointers.
  4. Actor clicks any bucket chain entry: editor jumps directly to the corresponding line in Monaco.
PostconditionsActor visualizes hash table load distribution and collision resolution.

7. Operational, Deployment & Verification Guide

7.1 Local Development Startup

To run the application locally on any workstation:

# 1. Install minimal dependencies (Express & CORS)
npm install

# 2. Start the local HTTP server (serves frontend & REST API)
npm start
# Output: Server running at: http://localhost:3000

# 3. Execute the full automated regression test suite
npm test

7.2 Static Server & Offline Deployment

Because the compiler engine (compiler.js) is 100% self-contained in the browser, the application can be hosted on any static web server with zero backend configuration:

  • VS Code Live Server: Right-click public/index.html → "Open with Live Server" (runs on port 5500 with zero errors).
  • GitHub Pages: Publish the public/ folder directly to GitHub Pages for instant, globally available web access.
  • Local File System: Double-click public/index.html to open via file:/// protocol.
